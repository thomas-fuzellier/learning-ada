# Lesson 01 — Getting started

**Phase 1 — Fundamentals**

Set up a professional Ada toolchain, with or without administrator rights, create a first
[Alire](https://alire.ada.dev) project, and learn the anatomy of an Ada program.
The build is configured so that any warning or style issue stops it.

Course notes (French): [`lecon_01_premier_programme.pdf`](lecon_01_premier_programme.pdf)

## Objectives

- Explain why Ada is used in safety-critical and defense systems.
- Install Alire, the GNAT compiler and GPRbuild, with or without administrator rights.
- Create, build and run a project with `alr init`, `alr build` and `alr run`.
- Read the structure of an Alire project: `alire.toml`, the `.gpr` file, `src/`.
- Write a program with `with`, `use`, `procedure`, `begin` and `end`.
- Print text with `Ada.Text_IO`: `Put`, `Put_Line`, `New_Line`, `Set_Col`.
- Follow GNAT naming, comment and layout conventions.
- Turn every warning and style message into a build error.

## Key points

### Toolchain

| Tool | Role | Closest equivalent |
|---|---|---|
| `alr` (Alire) | Project and dependency manager, installs the toolchain | `cargo`, `pip` + `venv` |
| GNAT | Ada compiler (GCC-based) | `gcc` |
| GPRbuild | Build tool driven by `.gpr` project files | `make`, CMake |

### Installation on Windows

Only the way `alr` itself is installed differs; everything after that is the same.

| Method | Admin rights | Steps |
|---|---|---|
| Installer | Yes | Run `alr-X.Y.Z-installer-x86_64-windows.exe` from the [Alire releases](https://github.com/alire-project/alire/releases). If `Get-Command alr` fails in a regular terminal, add `C:\Program Files\Alire\bin` to the system `PATH`. |
| winget | Yes | `winget install --id AdaLang.Alire --exact` |
| Zip archive | No | Extract `alr-X.Y.Z-bin-x86_64-windows.zip` into a user folder and add its `bin` directory to the user `PATH`. |

Then, in every case:

```sh
alr toolchain --select   # accept MSYS2, pick gnat_native and gprbuild
alr version
alr toolchain
```

Install the **Ada & SPARK** extension by AdaCore in VS Code. On Linux and macOS,
extract the archive and add its `bin` directory to the `PATH`.

Do not mix methods: two `alr` executables on the `PATH` make it unclear which one runs.

### Build steps

A build goes through three steps: **compile**, **bind** and **link**. The binder
(`gnatbind`) checks that every unit of the program was compiled consistently
and computes the elaboration order before the main procedure runs.

### Project layout

| Path | Content | Versioned |
|---|---|---|
| `src/` | Source code | Yes |
| `alire.toml` | Manifest: name, version, authors, license, build switches | Yes |
| `lesson_01.gpr` | GPRbuild project: source dirs, mains, compiler switches | Yes |
| `config/` | Generated by Alire on every build, never edited by hand | No |
| `obj/`, `bin/`, `alire/` | Build products and Alire internals | No |

### Anatomy of a program

```ada
--  Prints a greeting.
with Ada.Text_IO; use Ada.Text_IO;

procedure Hello is
   --  Declarative part: declarations only.
begin
   --  Statements.
   Put_Line ("Hello, ""Ada""!");
end Hello;
```

- `with` makes a package available; `use` makes its names visible without a prefix.
  `use` alone does not compile.
- A main program is a parameterless procedure; the `.gpr` file lists the mains.
- An empty body is illegal: "do nothing" is written `null;`.
- The name after `end` is optional, but if present it must match: a wrong name is
  a compilation error.
- A double quote inside a string literal is written twice: `""`.
  Single quotes denote one `Character`, never a string.

### Text output

| Procedure | Effect |
|---|---|
| `Put (S)` | Print without a line break |
| `Put_Line (S)` | Print, then move to the next line |
| `New_Line (Spacing => N)` | Print `N` line breaks (default `1`) |
| `Set_Col (C)` | Move to column `C`; if the column is already passed, go to the next line first |

### Style rules enforced in this repository

- Keywords in lower case, identifiers in `Mixed_Case_With_Underscores`,
  each reference spelled exactly as its declaration.
- 3-space indentation, a space before the opening parenthesis of a call,
  a space after each comma.
- A full-line comment has two spaces after `--`; an end-of-line comment needs at least one.
- File name = unit name in lower case (`Ex01_Banner` lives in `ex01_banner.adb`).
- A comment says *why* or *what the program does*; it must never contradict the code.

Every warning and style message is turned into an error in `alire.toml`:

```toml
[build-switches]
"*".compile_checks = "Errors"
```

Warnings only appear when a file is compiled, so a build that reports
"up to date" proves nothing. Force a full rebuild to check:

```sh
alr build -- -f
```

## Exercises

Each exercise is a separate main program declared in `lesson_01.gpr`.
Run one with `bin/<name>.exe` (Windows) or `bin/<name>` (Linux).

| # | File | Topic |

### Exercise 1 — Banner

Print exactly the following, without any `use` clause, using `Put`, `Put_Line`
and `New_Line` at least once each. The last line is built with two calls.

```
+----------------------------+
|        LEARNING ADA        |
|  Lesson 01: first program  |
+----------------------------+

Author: Thomas Fuzellier
```

### Exercise 2 — Mission brief

Print exactly the following, with a `use` clause and one comment per section
(header, mission details, conclusion). The `Operation` line is built with exactly
three calls, and blank lines come from `New_Line` only.

```
=============================
       MISSION BRIEFING
=============================

Operation: "Silent Falcon"
Status:    READY
Priority:  HIGH

Orders:
  1. Compile without warnings.
  2. Review every line.
  3. Report to command.

-- End of briefing --
```

### Exercise 3 — Fix me

Copy the program below as is, then fix it one compiler message at a time until
the build is silent. One problem is invisible to the compiler.

```ada
with Ada.Text_Io;
Use Ada.Text_IO;

procedure Ex03_Fix_Me is
   -- Fixed exercise
begin
  Put_Line ("Radar system online")
   put_line ("Tracking 3 targets");
   Put ("Status: ")
   Put_Line ('NOMINAL');
   New_Line();
end Ex03_FixMe;
```

### Exercise 4 — Target report

Print exactly the following. The three blank lines come from a single call, and
no string may contain spaces used for alignment: the `Status` column starts at
column 15. Find the right procedures in the specification of `Ada.Text_IO`
(`a-textio.ads`, reached with *Go to Definition* in VS Code).

```
TARGET REPORT



Name          Status
Alpha         Tracked
Bravo         Lost
Charlie       Tracked
```

<details>
<summary>Exercise 3 — Fix me</summary>

| Problem | Kind |
|---|---|
| Missing `;` after the first `Put_Line` and after `Put` | Syntax error |
| `'NOMINAL'`: single quotes denote one character | Syntax error |
| `New_Line()`: empty parentheses are not allowed | Syntax error |
| `end Ex03_FixMe;` does not match the procedure name | Compilation error |
| `Ada.Text_Io`, `put_line`: casing differs from the declaration (`-gnatyr`) | Style |
| `Use`: keywords are lower case (`-gnatyk`) | Style |
| `-- Fixed exercise`: one space after `--` (`-gnatyc`) | Style |
| Two-space indentation (`-gnaty3`) | Style |
| The comment says nothing about the program and sits in the declarative part | Not detected by the compiler |

Casing errors only appear once the syntax errors are fixed: they need semantic
analysis, which never runs on a file that does not parse.

```ada
--  Prints the radar system status report.
with Ada.Text_IO; use Ada.Text_IO;

procedure Ex03_Fix_Me is
begin
   Put_Line ("Radar system online");
   Put_Line ("Tracking 3 targets");
   Put ("Status: ");
   Put_Line ("NOMINAL");
   New_Line;
end Ex03_Fix_Me;
```

</details>

<details>
<summary>Exercise 4 — Target report</summary>

`New_Line` takes a parameter named `Spacing`, of type `Positive_Count`, with a
default value of `1`. `Set_Col` moves to a given column; if the current column is
already past it, it first moves to the next line.

```ada
--  Prints a target status table, aligned with Set_Col.
with Ada.Text_IO; use Ada.Text_IO;

procedure Ex04_Target_Report is
begin
   Put_Line ("TARGET REPORT");
   New_Line (Spacing => 3);

   Put ("Name");
   Set_Col (15);
   Put_Line ("Status");
   Put ("Alpha");
   Set_Col (15);
   Put_Line ("Tracked");
   Put ("Bravo");
   Set_Col (15);
   Put_Line ("Lost");
   Put ("Charlie");
   Set_Col (15);
   Put_Line ("Tracked");
end Ex04_Target_Report;
```

The literal `15` is repeated four times. Lesson 2 replaces it with a named constant.

</details>
